## 4. 总体设计（为什么这样改）

| 决定 | 做法 | 理由 |
|---|---|---|
| D1 | **待增值内部查两个小类，但交给出表和快照的主数据仍然是“一类”**（`结果["数据"]` 里类名还是 `增值服务`），每格 = 合箱 + 单箱 | 主表（`做组表`）、结论句、窗口、快照都只认这一类，数据样子不变，它们就**一个字都不用改**，现有展示自然不变 |
| D2 | 拆开的数字另放在 `结果["拆分"]`（和 `结果["数据"]` 一样的格式：`{小类: {区: 回查结果 或 "失败"}}`）；“全部”那次的数和核对结果放 `结果["拆分核对"]` | 和主数据分开，出错也不影响主表；格式和主数据一样，就能直接拿现有的 `做组表()` 出合箱表、单箱表 |
| D3 | 不用待拣货那种“两类直接放进主数据”的办法 | 那样窗口会多出「合计 / 合箱 / 单箱」切换（小柒要的是小卡片，不是切换），快照也会多出两类（「和上次比」会把改之前的记录当成“没有上次”） |
| D4 | 每个区内按 合箱 → 单箱 → 全部 的顺序查（区在外层、小类在内层） | 小柒写的顺序；三个总数离得近（同一个区一两分钟内），核对时受“任务一直在变”的影响最小 |

8. 返回和 `运行()` **一样的键**，另加 `"拆分": 拆分`、`"拆分核对": {区: {...}}`。

**新增 `_合并两类(甲, 乙)`**：两个 `回查()` 结果 → 一个同样格式的结果。规则：
| 字段 | 怎么算 |
|---|---|
| 任一个是 `"失败"` | 整个返回 `"失败"` |
| `全部` | 甲.全部 + 乙.全部 |
| `天` | 两边日期的并集；某天的值 = 甲那天 + 乙那天。某一边没有这一天时：那一边 `对上` → 当 0；没对上 → 这一天**不放进去**（不知道，不当 0） |
| `起点` | 两边起点里更早的（和待拣货“合计起点 = 两类里更早的”同一条规矩） |
| `对上` | 合并后的 `天` 加起来 == 合并后的 `全部` |
| `差` | `全部 − 天的和` |
| `查到` | 没对上时 = 合并后 `天` 里最早的日期；对上时不写这个键（和 `回查()` 一样） |

> 为什么这样就“展示不变”：`做组表()` 拿到的仍是一类、一样格式的数据。改之前每格是“全部”那天的数，改之后是“合箱 + 单箱”那天的数；探索 Q9 和第 10.3 节真实对照要证明这两个数相同。

**新增 `加拆分卡片(配置, 结果, 消息)`**：给 `消息["数量表们"]` 里每张表加一个可选键 `"格卡片们"`（第 7.2 节的格式）。只读 `结果["拆分"]`，算不出来就不加这个键（小卡片不出现，表照常）。整个函数包 `try/except`，出错只写一行日志，**绝不让结果变失败**。

### 6.2 “全部 = 合箱 + 单箱”的核对（写在 `运行拆分()` 里）
对每个区：`W = 拆分核对[区]["全部"]`，`A = 合箱.全部`，`B = 单箱.全部`，`允许 = 配置["核对允许差"]`（5），`K = W − (A + B)`。
> 小柒 03:29：“在查询的过程中，也会有一些待处理的任务被处理掉，所以有些许的误差是正常的，重新查询之后如果相差在一个合理范围内，就是没问题的。”
1. 三个都查到、`|K| ≤ 允许` → **通过**，不复查。日志：`K == 0` 写 `    核对：合箱 A + 单箱 B = W ✔`；`K ≠ 0` 写 `    核对：合箱 A + 单箱 B = S，全部 W，差 K 单，在允许范围内（≤5）✔`。
2. `|K| > 允许` → **马上复查一次**（第一轮的三个总数前后隔了一两分钟，这期间任务在变）：当前小类是“全部”，先查 W2；再改合箱查 A2（只查总数）；再改单箱查 B2；再改回全部。三次挨着查，前后十来秒。日志写出前后两组数。`K2 = W2 − (A2 + B2)`。
   - `|K2| ≤ 允许` → **通过**，日志写“复查后对上（差 K2 单，在允许范围内；任务在实时增减）”。表里的数仍用第一轮按天查出来的（合并结果自己是对得上的）。
   - `|K2| > 允许` → **不通过**：
     - 状态：“不完整”（橙色），数量照常写合计（不是 0、不是空）。
     - `结果["错误列表"]` 加一个 `自动化错误(数据不完整, 一句话)`，`步骤` 写“E区 核对“全部 = 合箱 + 单箱””。一句话固定格式：
       `E区：合箱增值 A2 + 单箱增值 B2 = S，任务小类“全部”是 W2，复查后“全部”比合箱 + 单箱多 N 单（超过允许的 5 单；可能还有别的任务小类，或查的时候任务在变），请到 WMS 看一下`
       （N = |K2|；K2 < 0 时把“多”换成“少”；“5”取 `配置["核对允许差"]` 的值）
     - 这样现有代码会自动：窗口错误块显示这句、飞书卡片的“⚠ 状态：不完整”下面写这句、运行记录和运行总表记“不完整”。**不另外改出表代码。**
   - 每个区不管通过没通过，都记 `结果["拆分核对"][区] = {"通过": True/False, "复查": True/False, "全部": W, "合箱": A, "单箱": B, "差": K}`（复查过的写复查后的数），Excel 核对表（5.4）和小卡片（7.2）都用它。
   - 通过（含有小误差的）：**不标 ⚠、不变橙色、不加错误**，状态照常。
3. 第三轮“全部”没查到（出错）：这个区的主表照常（合箱、单箱都查到了），但核对没做成 → 同样“不完整”，一句话：`E区：任务小类“全部”没查到，没法核对合箱 + 单箱（不是 0）`。
4. 合箱或单箱没查到：这个区主表本来就是“失败”，不再做核对，不另加错误。
5. **只复查一次**，不循环重查（防止越查越多、触发“访问频繁”）。
6. “不通过”那句话里的 K 用复查后的 K2；`允许` 的值也写进 `模块清单.md`，说明“小柒定的，想改就改配置里这一个数”。

### 7.2 数据：`数量表们[i]["格卡片们"]`（`加拆分卡片()` 生成，只有字符串和整数，能存进 `上次结果.json`）
```python
"格卡片们": {
  "10/30 周四（今天）|E区": {"标题": "E区 · 10/30 周四",
                            "行们": [["合箱增值", "120 单"], ["单箱增值", "35 单"]],
                            "合计": "155 单", "提醒": None},
```

- 键 = `行名|列名`，和变化表现有的 `提示们` 用同一种写法。**行名用 `做组表()` 出来的原样行名（去掉 `**`）**，不要用界面上加过“（这天及以前都是 0）”的名字（`数量表格.填` 里起点行会加这几个字，查键时要用加之前的名字）。

## 9. 查询变多：耗时和“访问频繁”风险

### 9.1 次数估算（每个区）
- 改之前：`1（全部）+ d（按天，直到 0）`，偶尔 +2（对不上时重查今天和总数）。
- 改之后：`[1 + d合] + [1 + d单] + 1（全部）`，偶尔 +2 / +2（各自对不上时）；第一次核对差超过 5 单时再 +3（复查，最多一次）。
- d合、d单 一般都不超过 d，所以**大约是原来的 2 倍**。
- 以前测过每次查询约 2.5 秒；10/23 记录里 D区待增值按天要查 4–10 天【已核对：当时 0 日 10/20】。按这个算：瑞江（D+E）约 20 次 → 40 次左右，约 1 分钟 → 2 分钟左右；松户（A+C+F）更多【未验证，以探索第 Q10 和第 10.3 节实测为准】。
- 下拉框切换（任务小类、所属区域）不算查询，但每次切换照现有 `下拉选择()` 有 0.3–0.5 秒等待，不要删。

### 9.2 不许做的提速
不减查询间隔、不并行、不跳过“全部”那次核对、不跳过按天查（例如“总数是 0 就不按天查”——这会改 `回查()` 的行为，这次不做）。

### 9.3 防“访问频繁”
- 沿用 `任务查询.py` 的整次运行共用间隔：一旦出现“点击次数过多”，这次运行后面所有模块都按 2 秒一次。
- 核对只复查一次（6.2 第 5 条）。
- 探索有 80 次上限（3.2）。
- **【必须】核对一件事并写进报告**：现在的 `公共\错误.py` 里，“立刻停下”只有 `账号被挤`、`WMS提示` 两类（WMS 弹出提示框时归到这里）。执行方要确认：
  1. WMS 提示“访问频繁”时，是不是以弹框出现、会被归到 `WMS提示` 而立刻停；
  2. 运行中途被踢回登录页时，现在的代码会不会发现并停（还是只会报“找不到元素”再去查下一个区）；
  3. 出现验证码时同上。
  任何一条“不会停”：在 `公共\错误.py` / `公共\任务查询.py` 加上识别，归到 `立刻停下`；这是安全检查，按 `CLAUDE.md`“小而有用的检查可以自己加，做完告诉小柒”，写进报告。**不能**写成“遇到了就等一会儿再试”。没法验证的（例如从没见过“访问频繁”长什么样）写【未验证】。
- 进度条：`运行总表.csv` 里待增值的历史用时会让进度条第一次估短，属于正常，跑几次后自己变准；报告里写一句即可，不改进度条代码。
